## 背景与目标

企业级竞品/行业调研 Agent：用户通过统一 Web 控制台输入**单个目标 URL** 并点击「开始调研」，系统异步完成「采集 → 解析 → 切分 → 向量化（对外 Agent）」与「检索聚合 → 结构化结论生成 → 模拟回填内部系统（对内 Agent）」，并将结果**三步渐进式回填至同一页面**（预览区 / 知识切片区 / 结论回填区）。

架构基石为 PRD §1.2 三大铁律，作为本 SPEC 的约束性边界（详见 R3）：

1. **代码解析优先**：能通过 DOM/CSS 提取的信息，禁止调用多模态大模型；截图仅用于留痕与人工复核。
2. **性能左移（胖采集）**：解析、切分、向量化等 CPU/内存密集任务全部下沉至对外 Agent。
3. **瘦内耗**：对内 Agent 仅做 Top-K 检索聚合与轻量 LLM 生成，可在 2 核 4G 环境运行。

编排框架锁定 LangGraph（Supervisor 主控图 + 对外/对内双轨并行子图）；后端 FastAPI，前端 MVP 单页控制台（选型见 R2）。

## 范围

依据 PRD §8.1–8.3，V1（MVP）交付范围：

1. **后端——对外子图（Web Acquisition，「写入」轨）**：
   - 单 URL 异步采集管道：Playwright 渲染抓取（主），CDP Turbo 加速；
   - BeautifulSoup + CSS 语义推断提取正文/价格等字段，并绑定节点 BoundingRect/XPath；
   - 按 H1/H2 标题语义切分为 512–1024 tokens 的 `pre_chunks`（附 `section_path` 与 `xpath` 可溯源）；
   - 整页/视口截图落盘（不做像素级分析）；
   - 轻量 Embedding 模型生成文本向量，随标准 Payload（PRD §6.2）转交对内。
2. **后端——对内子图（Internal RAG，「读取+回写」轨）**：
   - 接收对外 Chunks+向量，结合内部知识库做 Top-K 混合检索（**禁用 Rerank**）；
   - `with_structured_output` 强制生成符合内部 API Schema 的结论 JSON；
   - 末节点 Tool Node **模拟** POST 回填内部系统，捕获回调状态（成功/失败/工单号）。
3. **前端——单页 Web 控制台**：
   - 一个 URL 输入框 + 一个「开始调研」按钮；
   - `POST /api/task` 提交 + `GET /api/task/{id}/stream`（SSE）进度推送（10% / 50% / 100%）；
   - 三块回填区：Step 1 预览区（整页截图缩略图 + 标题/Meta/状态码）；Step 2 知识切片区（实时展示 `pre_chunks`）；Step 3 结论回填区（结构化结论卡片 + 回填状态回执）。
4. **状态机**：Pending → Fetching → Parsing → RAGing → Done，各状态经 SSE 可观测。
5. **界面层简易权限**：普通调研员仅见 Step 1+2；决策层/管理员可见 Step 3 并可手动「重新生成」触发对内子图重跑（V1 以最小实现为准，不引入账号体系，见非范围）。

## 非范围

依据 PRD §8.4 及铁律推论，V1 **不做**：

1. 多 URL 批量采集 / 批量上传 / 任务历史列表（V2.0+，PRD §9.2）；
2. 像素级视觉分析、多模态大模型看图理解（违反铁律一；截图仅留痕复核）；
3. 复杂权限管理 / 账号认证体系（V1 仅界面层角色区分的最小实现）；
4. 动态反爬策略与代理池（V2.0+，PRD §9.1；V1 反爬失败按 failure_paths 处理）；
5. 对内接入真实企业 OA/CRM/Jira 审批流（V1 仅模拟回填；真实接入为 PRD §9.3）；
6. 私有化大模型部署（POC 用 API；生产切换为 PRD §9.4）；
7. 检索重排序（Rerank）（铁律三资源约束，显式禁用）。

## 验收标准

全部为可观测判定：

| # | 验收项 | 可观测判据 |
|---|--------|-----------|
| A1 | 异步提交与进度 | 输入合法 URL 点击「开始调研」后，前端不经 HTTP 超时即收到任务 ID；SSE 流中可依次观测到进度事件（10% / 50% / 100%）与状态机迁移 Pending→Fetching→Parsing→RAGing→Done |
| A2 | Step 1 预览区 | 任务进入 Fetching 完成后，预览区渲染目标页整页截图缩略图，并显示标题、Meta、HTTP 状态码 |
| A3 | Step 2 知识切片区 | 切片区实时展示对外 Agent 产出的 `pre_chunks`（每条含标题/正文片段）；每条 chunk 附带 `section_path` 与 `xpath` 字段，且块长落在 512–1024 tokens 区间 |
| A4 | Step 3 结论回填区 | 对内子图完成后，结论区渲染结构化 JSON 结论卡片（含竞品价格、风险等级、建议动作三字段），非纯文本报告 |
| A5 | **闭环验证（PRD §8.3，一票否决项）** | 页面底部出现「已模拟写入内部系统（工单号：xxx）」成功提示，工单号非空且与 Tool Node 模拟回调返回值一致 |
| A6 | 铁律一可审计 | 全流程日志中无多模态/视觉模型调用记录；截图文件落盘路径在 Payload `screenshot_path` 可追溯 |
| A7 | 铁律三资源上限 | 对内 Agent 进程在 2 核 4G 限制环境下完成一次完整任务不 OOM、不触发重试风暴（单次任务内存峰值 ≤ 可约定阈值，建议 ≤3GB） |
| A8 | 权限最小实现 | 以调研员视角打开页面时 Step 3 不可见；以管理员视角可见 Step 3 且「重新生成」按钮可触发对内子图重跑并刷新结论区 |
| A9 | 失败可见性 | 任一 failure_paths 行触发时，页面出现对应错误提示且任务状态不滞留中间态（终态为 Done(失败) 或 Error） |

## 失败路径（failure_paths）

| 触发条件 | 系统行为 | 可重试 | 用户可见 |
|----------|----------|--------|----------|
| 目标页抓取超时（Playwright 超时阈值内未完成渲染） | 对外子图标记 Fetching 失败，任务转终态 Error；保留已落盘的部分截图（若有）供复核 | 是（用户重新提交同一 URL；V1 不自动重试） | 页面提示「目标页面抓取超时，请稍后重试」+ 状态 Error |
| 目标站反爬拦截（403/验证码/重定向到验证页） | 检测响应状态码与验证页特征，终止管道，状态 Error；截图留痕 | 是（重试语义同超时；代理池属非范围，不承诺成功率） | 页面提示「目标站点拒绝访问（反爬拦截）」+ 状态码 |
| 代码级解析为空（DOM/CSS 提取无有效正文） | **不降级**调用多模态模型（铁律一）；以空 chunks 继续流转，对内子图产出「信息不足」结论 JSON | 是（用户可换 URL 重试） | 切片区显示「未提取到有效内容」；结论区显示信息不足结论 |
| 对内回填 API（模拟 Tool Node）失败 | 捕获回调失败状态，结论区仍展示已生成结论 JSON，回执区标注「写入失败」及原因；任务终态 Done(回填失败) | 是（管理员点「重新生成」重跑对内子图） | 页面底部显示「模拟写入失败：原因」而非成功工单号 |
| SSE 连接中断（网络抖动/服务重启） | 前端按任务 ID 断线重连并补拉当前状态；后端任务状态不丢失（内存态可接受，须日志可查） | 是（前端自动重连，上限后提示刷新） | 进度条停滞超过阈值时提示「连接中断，正在重连」 |
| 2核4G 资源超限（对内 Agent 内存逼近上限） | 对内子图降级为截断 Top-K（减少检索条数）完成生成；记录降级日志 | 否（任务继续完成，质量降级） | 无感知；日志可观测降级事件 |

## 思考轮（10-spec 回填）

### R0 · 读人聊 / 业务目标

输入真值为 PRD V2.0 原文（2026-09-09 会话输入，`_source/PRD_web_research_agent_v2.md`）。业务目标一句话：**企业调研员在一个 Web 页面里输入竞品/行业目标 URL，系统自动完成采集分析，并把结构化结论连同「已写入内部系统」回执回填到同一页面**。PRD 新增核心为 §3（三步渐进式回填交互）与 §4.3（智能切分下沉对外 Agent）；三大铁律（§1.2）为不可协商的架构约束。PRD 语义未改写，本 SPEC 全部条款可回溯至 PRD 章节号。

### R1 · 范围 / 非范围 / 角色与场景

- **角色**：普通调研员（发起任务、复核 Step 1+2）；决策层/管理员（查看 Step 3、触发重新生成）。V1 不建账号体系，角色区分仅界面层最小实现（如 URL 参数或简单开关），已在范围第 5 条与非范围第 3 条双向锁定。
- **主场景**：单 URL → 异步任务 → SSE 进度 → 三段回填 → 底部模拟工单回执（A5）。
- **范围**按 PRD §8.1–8.3 落为后端对外/对内双轨 + 前端单页控制台 + 状态机；**非范围**按 §8.4 + 铁律推论显式排除批量、视觉分析、复杂权限、代理池、真实审批流、私有化 LLM、Rerank。范围/非范围无重叠灰色项；唯一边界讨论点为「截图留痕」属于范围（存储+展示）而「截图内容分析」属非范围，已在 A6 与 failure_paths「解析为空不降级」双向钉死。

### R2 · 方案对比（≥2 · 推荐 · 弃选）

**分叉一：前端 MVP 框架（PRD §7）——Streamlit vs Flask + Jinja2**

| 维度 | Streamlit | Flask + Jinja2（推荐） |
|------|-----------|------------------------|
| SSE 流式推送（PRD §3.1 硬需求） | 原生无 SSE 概念，进度靠轮询/rerun 模拟，与 `GET /api/task/{id}/stream` 契约错位 | Flask 原生支持流式响应/SSE，与 FastAPI 后端契约一致（或同进程直接挂 SSE 端点） |
| 三块区域渐进式回填 | rerun 模型下局部更新需 session_state 技巧，三块异步刷新易闪烁 | 模板渲染 + 原生 fetch/EventSource 逐区回填，布局完全可控 |
| 权限分区（Step 3 角色可见性） | 组件级隐藏可做但非其设计重心 | 模板条件渲染天然支持 |
| 开发速度 | 极快（纯 Python 无前端代码） | 快（单页模板 + 少量 vanilla JS） |
| V2 演进（批量 URL、任务历史，PRD §9.2） | 多页/状态管理天花板低 | 可平滑加页或内嵌渐进增强 |

**推荐：Flask + Jinja2**。决定性理由是 SSE 契约与三块异步回填为 PRD §3.1/§3.2 硬需求，Streamlit 的 rerun 模型与之结构性冲突；省下的前端工作量会在 SSE 模拟与权限分区上加倍还回。**弃选 Streamlit**：仅当「砍掉 SSE 改轮询 + 不做权限分区」的降级 MVP 才成立，而该降级违背 PRD §3.1 明文，故弃选。

**分叉二：向量库（PRD §7）——FAISS vs Qdrant**

| 维度 | FAISS（推荐 · V1） | Qdrant（V2 生产候选） |
|------|--------------------|------------------------|
| 资源占用（铁律三 · 2核4G） | 进程内库，零额外服务，内存可控 | 独立服务进程，常驻内存叠加，2核4G 下与对内 Agent 争资源 |
| 运维复杂度（MVP 单机/单容器） | pip 依赖，无部署项 | 需额外容器/服务编排 |
| Top-K 混合检索能力 | 向量检索充足；标量过滤需自行拼接，V1 检索需求简单可承受 | 原生 payload 过滤与混合检索，适合多租户/多任务生产形态 |
| 持久化与多任务扩展 | 索引文件自行管理，V1 单任务可接受 | 集合级管理，V2 批量/历史场景必需 |

**推荐：FAISS（V1）**，理由：铁律三资源约束 + MVP 单任务场景下零额外服务是硬优势；Qdrant 能力超出 V1 需求。**弃选 Qdrant（仅 V1 阶段）**：在 2核4G 约束下引入独立向量服务属过度工程；保留为 V2 批量采集（PRD §9.2）时的迁移候选，接口层应抽象以便替换（建议写入 task 的非功能约束）。

### R3 · 边界 / 失败路径 / 安全与依赖

**三大铁律边界（不可协商）**：

1. **代码解析优先**：边界 = 截图只允许「落盘存储 + 页面展示 + 人工复核」，禁止任何以截图为输入的模型调用。失败路径「解析为空」的处置是产出「信息不足」结论而**非**降级到多模态，此边界已在 failure_paths 与 A6 双向锁定。
2. **性能左移（胖采集）**：边界 = 解析、切分、Embedding 全部发生在对外子图；对内子图收到的 Payload（PRD §6.2）已含向量，对内禁止重复计算 Embedding。对内仅允许 Top-K 检索 + 轻量生成 + Tool 调用，且禁用 Rerank。
3. **瘦内耗 2核4G**：边界 = 对内 Agent 必须在该资源盒内运行（A7）；唯一允许的降级手段是截断 Top-K（见 failure_paths 末行），不允许引入常驻重服务（此条支撑 R2 向量库选 FAISS）。

**失败路径**：已在「失败路径」表覆盖 PRD 明示与可预见的六类：抓取超时、反爬拦截、解析为空、回填 API 失败、SSE 中断、资源超限降级。关键设计：解析为空**不降级**；回填失败**不丢结论**（结论区照出，仅回执标失败）；所有失败均落终态，不留僵尸任务。

**安全与依赖**：Playwright（+CDP）渲染第三方站点存在 SSRF 面，建议 task 阶段约束目标 URL 协议白名单（http/https）与内网地址段拒绝（列入 test_strategy）；依赖锁定 FastAPI / LangGraph / Playwright / BeautifulSoup / 轻量 Embedding 模型 / FAISS；LLM POC 期走外部 API，Key 管理属 task 实现细节但 SPEC 要求不落盘明文（建议项）。

### R4 · 验收标准 / 可测性 / test_strategy 建议

验收表 A1–A9 全部为可观测判据，其中 **A5（页面底部出现「已模拟写入内部系统（工单号：xxx）」）为一票否决闭环项**，直接对应 PRD §8.3。可测性设计上，对外/对内双轨天然支持 PRD §2.2 的并行开发：对内子图可用 Mock Payload（PRD §6.2 契约）独立闭环测试，对外子图无需内部大模型。

`test_strategy` 建议（供 10-task 采纳拆分）：

1. **契约测试**：PRD §6.2 标准 Payload 的 JSON Schema 校验（对外产出 / 对内消费双向）；
2. **对内子图单测**：Mock chunks+向量 → 断言结构化 JSON 结论字段齐全（价格/风险等级/建议动作）+ Tool Node 模拟回填返回工单号；
3. **对外子图集成测试**：本地静态测试页（含 H1/H2/价格 DOM）→ 断言 pre_chunks 块长 ∈ [512,1024] tokens、section_path/xpath 非空、截图落盘；
4. **E2E 闭环**：真实（或本地镜像）目标页 → 点击开始调研 → 断言 SSE 事件序列与底部工单号回执（A1+A5）；
5. **失败注入**：超时（慢响应桩）、反爬（403 桩）、空解析（空 body 桩）、回填失败（500 桩）四条 failure_paths 各一用例，断言用户可见文案与终态；
6. **资源测试**：对内 Agent 在 2核4G 限制（如容器限额）下跑 E2E，断言内存峰值阈值（A7）；
7. **安全用例**：file://、内网 IP 段 URL 被拒绝（SSRF 白名单）。

**SPEC 签收就绪**。范围/非范围/验收/failure_paths 全部落实为可观测表述并逐条回溯 PRD 章节；R2 两个 PRD §7 选型分叉已给推荐与弃选理由；R3 三大铁律边界与六条失败路径已钉死；R4 验收含 §8.3 闭环一票否决项且 test_strategy 可拆分。**建议路径：本 SPEC 经轻量 20-spec-audit 书面审 → 人签 HG-SPEC-SIGNOFF → 00 按双轨（对外子图 / 对内子图 / 前端控制台）拆 task**。无 freeze_id 级契约变更待升级（PRD §6.2 Payload 契约沿用原文）。
