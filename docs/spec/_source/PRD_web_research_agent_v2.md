# 产品技术大纲（完整版 V2.0）：智能网页调研Agent

> 来源：用户提供的 PRD 原文（2026-09-09 会话输入），作为 SPEC 思考的 R0 输入真值，禁止改写语义。

1. 项目定位与核心原则
1.1 产品目标：企业级竞品/行业调研Agent，用户通过统一Web控制台点击URL，自动完成采集分析并将结论回填至当前页面。

1.2 三大铁律（架构基石）：

代码解析优先：能通过DOM/CSS提取的，绝不调用多模态大模型（截图仅留痕与人工复核）。

性能左移（胖采集）：所有CPU/内存密集型任务（解析、切分、向量化）下沉至对外Agent。

轻量推理（瘦内耗）：对内Agent仅做检索聚合与轻量LLM生成，目标2核4G可运行。

2. 整体架构设计（LangGraph框架）
2.1 编排模式：Supervisor（主控图） + 并行子图（Sub-Graphs）。

2.2 双轨并行开发策略：

对外子图（Web Acquisition）：负责“写入”。独立开发，无需依赖内部大模型。

对内子图（Internal RAG）：负责“读取+回写”。可Mock外部数据，专注逻辑闭环。

2.3 部署形态：后端服务（FastAPI）+ 前端Web控制台（同机部署或容器内网互通）。

3. 用户交互与前端回填设计（新增核心章节）
3.1 统一Web控制台交互：

操作极简：仅一个输入框（输入目标URL） + 一个“开始调研”按钮。

异步提交通信：因对外采集耗时长，采用 POST /api/task 提交 + GET /api/task/{id}/stream (SSE轮询) 模式，避免HTTP超时。

3.2 三步渐进式回填布局（同页面三块区域）：

Step 1 - 预览区（顶部/左侧）：任务启动后立即渲染目标网站的整页截图缩略图 + 基础元数据（标题、Meta、状态码）。

Step 2 - 知识切片区（中部）：实时展示对外Agent切分好的 pre_chunks（如“段落1：产品特性”），让用户肉眼确认Agent“看”到了哪些有效信息。

Step 3 - 结论回填区（底部/右侧）：对内Agent完成后，自动填入结构化结论（竞品价格、风险等级、建议动作），并高亮显示“已自动写入内部OA系统”的状态回执。

3.3 权限与可观测性（界面层）：

普通调研员：仅可见 Step 1 + Step 2（用于人工复核数据准确性）。

决策层/管理员：可见全量 Step 3，并能手动点击“重新生成”触发对内子图重跑。

4. 对外Agent（信息获取与预处理）—— 性能重灾区
4.1 网页渲染与抓取：技术选型锁定 Playwright（优先），配合CDP协议实现Turbo加速。

4.2 代码级精准解析（核心）：

利用 BeautifulSoup + CSS 语义推断（微格式），精准提取价格、SKU、文本正文。

获取每个节点的 BoundingRect 坐标，为文本绑定位置信息（便于截图标注）。

4.3 智能切分（新下沉职责）：

按 H1/H2 标题语义切分清洗后的文本，每块控制在 512-1024 tokens。

切分块附带父级路径（section_path）和 Xpath 坐标，保证可溯源。

4.4 视觉处理（辅助）：仅整页/视口截图落盘存储，不做任何像素级视觉分析。

4.5 向量化：调用轻量 Embedding 模型生成文本向量，随 Payload 一并转交对内。

5. 对内Agent（RAG整合与系统交互）—— 极简轻量
5.1 接收与轻量检索：接收对外现成的 Chunks 和向量，结合内部知识库做 Top-K 混合检索（禁用重排序 Rerank 以节省资源）。

5.2 结构化结论生成：利用 LangGraph 的 with_structured_output 强制生成符合内部系统 API Schema 的 JSON（摒弃纯文本报告）。

5.3 工具节点自动回填（Tool Node）：

Graph 最后一个节点绑定企业内部系统（OA/CRM/Jira）的 POST API Tool。

将结论 JSON 自动推送至内部工单或审批流，并捕获回调状态（成功/失败/工单号）。

6. 完整数据流转与状态定义（State Schema）
6.1 前端交互流：Web UI输入URL → 后端异步任务队列 → SSE推送进度(10%, 50%, 100%) → 三段式回填页面。

6.2 后端跨子图通信契约（标准Payload）：
```json
{
  "url": "xxx",
  "screenshot_path": "/static/shot.png",
  "extracted_meta": {"title":"", "price":""},
  "pre_chunks": [{"title":"产品参数", "text":"...", "embedding":[...], "xpath":"..."}]
}
```
6.3 状态机：Pending（排队） → Fetching（抓取中） → Parsing（解析切分） → RAGing（内部检索） → Done（已回填）。

7. 技术栈与基础设施选型（更新）
层级	技术选型	说明
后端框架	FastAPI	提供异步接口与 SSE 流式推送
前端框架（MVP）	Streamlit 或 Flask + Jinja2 模板	快速验证“一个页面三个区”，无需前后端分离
工作流编排	LangGraph (Python)	双轨子图并行开发
浏览器自动化	Playwright（主）、Puppeteer/CDP（备选）	—
向量库	FAISS（轻量，MVP） / Qdrant（生产）	—
大模型调用	对外（可选API做摘要）、对内（POC用API，生产切私有化）	—

8. MVP（V1.0）交付范围
8.1 后端交付：单URL的异步采集管道（对外：抓取+解析+切分；对内：Mock检索+JSON生成+模拟API回填）。

8.2 前端交付：一个可用的Web页面，具备“输入框”、“进度条”、“三块回填区”（截图、切片文本、结论卡片）。

8.3 闭环验证：点击URL后，页面底部必须出现“已模拟写入内部系统（工单号：xxx）”的成功提示。

8.4 非目标（V1不做）：多URL批量采集、像素级视觉分析、复杂权限管理。

9. 后续规划与扩展点（V2.0+）
9.1 引入动态反爬策略与代理池（对外加固）。

9.2 前端支持批量上传URL，并引入任务列表历史记录。

9.3 对内接入真实企业权限审批流，而非仅模拟回填。

9.4 全面迁移至企业内部私有化大模型。
